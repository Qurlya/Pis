# Лабораторная работа №4. Итоговое задание

**Это задание общее для всех вариантов и не привязано к конкретной
теме — выполняется оно на сайте именно вашего собственного варианта:
той темы, которую вы реализовывали в Лабораторной работе №2 и уже
переносили на компоненты по ходу тем 1–9. Не копируйте сайт из
примеров ниже — все названия, страницы и разделы в этом файле условные
и служат только для иллюстрации формата. Каждый пункт чек-листа нужно
применять не буквально, а по смыслу: сами решайте, где на вашем сайте
естественно применить конкретный приём, исходя из логики и реального
функционала именно вашего сайта.**

## Условие

Возьмите дизайн и структуру страницы, которую вы реализовывали в
Лабораторной работе №2 (HTML/CSS), и воссоздайте её один в один в виде
React-приложения на основе своего проекта (в примерах он называется
`lab-04-react`, у вас папка может называться иначе) — та же вёрстка, тот
же внешний вид, но теперь через компоненты и JSX вместо статичного HTML.

Названия страниц, компонентов и их содержимое в примерах ниже —
иллюстративные: если у вашего сайта из ЛР2 другие названия страниц и
разделов, ориентируйтесь на чек-лист по смыслу и используйте свои
названия, а не переименовывайте сайт под пример.

Дополнительно к пересобранному сайту нужно добавить:

- **вторую страницу (экран)** — переключается кнопкой из основного
  сайта, без перезагрузки страницы;
- **модальный контейнер** — всплывающее окно поверх сайта с
  затемнением/размытием фона, открывается и закрывается по кнопке.

Кроме внешнего вида, в пересобранный сайт нужно осмысленно встроить
приёмы из каждой темы лабы — не как оторванные демо-вставки, а по делу,
там, где они естественно нужны сайту (например, форма обратной связи —
это и есть controlled-компонент из темы 7, а не искусственная вставка
ради галочки).

## Чек-лист по темам (обязательный минимум)

1. **Компоненты и JSX** — сайт разбит минимум на 4–5 отдельных
   компонентов по смыслу (например `Header`, `Footer`, `Card`,
   `Gallery` — не всё одним большим `App`).
2. **Props** — минимум один компонент переиспользуется несколько раз с
   разными props (например карточка товара/услуги/проекта — под то, что
   было на сайте в ЛР2).
3. **State** — минимум два независимых `useState` в проекте.
4. **События** — минимум три разных типа событий на сайте (`onClick`,
   `onChange`, и ещё один — `onSubmit`, `onMouseEnter` и т.п.).
5. **Условный рендеринг** — минимум два разных приёма из темы 5
   (например тернарник для одного случая и `&&` для другого).
6. **Списки и key** — минимум один блок сайта, где данные (карточки,
   пункты меню, отзывы — что подходит по содержанию), рендерятся через
   `.map()` с корректным `key`.
7. **Формы** — минимум одна форма (например обратная связь/подписка)
   как controlled component: `value` + `onChange`, `onSubmit` с
   `e.preventDefault()`.
8. **useEffect** — минимум один осмысленный эффект (например живой
   таймер, счётчик просмотров, имитация загрузки данных при открытии
   страницы).
9. **Подъём состояния** — минимум одна пара компонентов-соседей,
   которые синхронизированы через общий state в родителе (а не
   общаются напрямую и не дублируют state).
10. **CSS** — переносится **весь** CSS из ЛР2: все стили сайта
    воссоздаются через `className`, как и было в оригинале (родные
    стили ЛР2 реально участвуют и используются в ЛР4, а не пишутся
    заново с нуля мелкими демо-фрагментами). Дополнительно — хотя бы
    один осмысленный случай `style={{}}` именно там, где значение
    реально вычисляется динамически (а не для галочки).
11. **Второе окно** — переключение реализовано через `state` + условный
    рендеринг (без перезагрузки страницы).
12. **Модальный контейнер** — реализован через `state` + условный
    рендеринг + CSS (`position: fixed`, `backdrop-filter: blur()`,
    кнопка открытия и закрытия).

## Организация файлов

В отличие от практики по темам 1–9 (которая велась в одном `App.jsx`) —
итоговый проект оформляется уже в отдельных файлах на каждый смысловой
компонент, с понятными именами (`Header.jsx`, `ContactForm.jsx`,
`AboutPage.jsx`, `Modal.jsx` и т.д.), с корректными `import`/`export` и
правильно настроенным `main.jsx`.

Чек-лист при переносе компонента в новый файл, чтобы не было ошибок:

- у нового файла обязателен `export default ИмяКомпонента` в конце;
- в файле, который его использует, — обязателен `import ИмяКомпонента
  from './ИмяФайла.jsx'` вверху;
- если новый компонент — это по сути новая «точка входа» вместо `App`,
  то `main.jsx` тоже нужно поправить — он всегда должен `import`-ить и
  рендерить именно тот компонент, который сейчас является актуальным
  корневым;
- не забывайте переносить/объявлять весь нужный `state` (`useState`) и
  импорты (`useState`/`useEffect` из `'react'`) вместе с компонентом.
